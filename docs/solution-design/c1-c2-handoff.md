# C1 → C2: Controlled Alternative Comparison Plan

**Status:** Protocol proposal; no trials conducted, no measured winner, no weights approved.

## Objective

Compare A physical/procedural, B QR/forms, and C integrated lifecycle concepts on the **same realistic Alaknanda tasks**. Determine whether added digital complexity yields enough incremental accountability to justify user burden and operating cost. Preserve physical storage controls as relevant to each alternative.

## Scenario coverage

The full [B4 scenario-to-concept matrix](c1-scenario-design-matrix.csv) maps **all 32 tests** to the design response in A/B/C. Highlight these high-information scenarios for matched pilot tasks:

1. At night the first guard-key signer is not the eventual item borrower (T01–T02).
2. Two residents collect equipment during one shared key session (R03 / T01).
3. Two residents seek same physical racket; avoid double issue (T08).
4. On-ground team sharing versus off-ground responsibility transfer (T09).
5. Reported return is contradicted by a missing item (T10).
6. Captain kit fast lane before match; missing component at return (T05, T11).
7. Damaged item is discovered with unknown occurrence time and cannot be reissued as verified usable (T12–T16).
8. Off-line/manual event clashes with newer issue; explicit conflict handling (T26).
9. Independently audit location, accountable entity, condition, including unknown versus contradicted (T22, T32).
10. Procurement threshold and receipt discrepancy without unauthorized approvals (T18–T20).

## Comparable experimental design

- Consent-based, **staged** scenarios first: same equipment set, task scripts, actors or matched groups and controlled ground truth. Randomize concept order where practical; separate learning effects. Study should be clearly marked *staged*, not live.
- Measure **actual** user and guard/custodian seconds and skipped steps, task completion, wrong / unresolved states, report latency, process interruptions, and physical audit triad-accountability n/N. Attach sample size and method.
- Evaluate cost: physical materials, setup training, recurring write/scan effort, hosting/dev maintenance; report observed versus estimated costs distinctly.
- For paper option A, observe whether double issue or missed entries are merely **reconciled later**; do not score it as automatic prevention.
- Test return/inspection separately; unknown and unverified fields are not falsely scored as verified correct.
- Include end-to-end physical trial evidence rather than scoring candidates exclusively on pretty wireframes.

## Decision gates requiring user approval before tests or rollout

1. Which items are tagged individually vs accounted by lots; who is independently responsible for verification without turning guard into inspector.
2. Whether team custody continues during on-ground sharing; off-ground transfer authorization.
3. Allowed interaction budget at match-time, condition-check risk policy, usable-vs-unknown restriction.
4. Data privacy permissions, consenting participants, physical asset use and pilot authority.
5. Criteria weights or explicit noncompensatory guards. **No invented weighted scores**, premature rank, or winner.

## C2 outputs to build

- `c2-comparison-protocol.md` with scripted tasks, crossover schedule, sampling and operational definitions.
- Printable and electronic C2 observation sheets; anonymized results and data dictionary.
- Recorded A/B/C demonstrations using physical props or consented participants (when user provides access).
- Comparison table with sources, results and limitations; evidence-backed selection memorandum only after tests.

C1 artifacts are **design representations only**. C2 can begin as a protocol without needing completed field measurement, but cannot claim any candidate improves real outcomes without real trials.
