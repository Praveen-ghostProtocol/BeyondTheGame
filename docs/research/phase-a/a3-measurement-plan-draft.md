## Proposed primary and secondary metrics

| Metric | Operational definition | Needed source | Notes |
| --- | --- | --- | --- |
| Request fulfilment rate | Valid requests fulfilled with usable equipment within an agreed service window / all valid requests | Sampled requests or controlled observed pilot | Service window *must be agreed before measurement*; avoid conditioning on successful requests only |
| Item-record agreement | Items correctly accounted for in records / sampled physical items | Anonymized physical stock-to-register check | Exact method depends on availability of item IDs; item count also valuable |
| Usable availability | Number usable and locatable / number active assets | Condition inventory | Define consumables separately; ignore retired assets in denominator |
| Issue elapsed time | Time from contacting guard to taking possession | Stopwatch/observation | Separate dorm travel from guard interaction, room access, search, actual handover |
| Return elapsed time | Return approach to completed key/ID exchange | Stopwatch/observation | Reported return is not necessarily verified condition |
| Damage detection delay | Time damage occurred to time secretary was notified | Documented cases | May be unmeasurable if time of damage unknown; explicitly report missingness |
| Repair turnaround | Time secretary reports/records issue to item restored or discarded | Repair cases, invoices | Separate approval, vendor and transport delays |
| Admin effort | Minutes secretary/guard spends per related task | Time diaries or recalled estimates | Avoid equating total calendar duration with person-minutes |
| Tournament documentation exception | Number kit issues bypassing register / total kit issues | Anonymized captain events | Sample, not claims about every tournament |
| Purchase lead time | Need recognized → equipment physically available | Quotes, office payments, receipts | Separate below/above ₹10k reported policy routes |

## Ethical lightweight collection options

1. **Records-based:** read register entries in a permitted setting; report anonymous daily/hourly counts and elapsed times. Never upload raw personal pages or signatures to public repo.
2. **Secretary reconstructed:** use actual invoice/damage chronology with documentary support if available, clearly note recollection.
3. **Observed mini-sample:** observe or enact equipment-handling tasks with consent and note measured timestamps; distinguish a staged test from routine operations.
4. **Inventory sample:** count selected categories and mark usable/damaged/unknown using non-identifying item IDs.

Use [transaction observation template](../../../data/templates/transaction-observation-template.csv), but only fill fields actually observed. Proposed new tools can be generated after input format and permission are confirmed.
